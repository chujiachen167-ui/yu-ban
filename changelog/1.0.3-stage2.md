# 1.0.3 · 补上阶段二：翻译不再等语音，四种状态分得开

日期：2026-10-07（句组对照之后，同一候选版内的第二批改动）。

## 改了什么

- **翻译不再被语音配置挡住。** 以前保存设置时会先校验语音，语音没配好就直接报错退出，你刚填好的翻译 Key 存不进去。现在翻译先保存，语音的问题单独在下面说明一句。
- 填了千问工作空间 Key 但没填工作空间 ID 时，可以直接取消弹窗：翻译照常保存，两把填好的 Key 都留着。
- 浮窗上**四种状态分得开**了：翻译中、朗读中、失败、取消。翻译中在重试按钮的位置显示等待点（别的按钮不移动）；失败会说明原因并保留重试入口；取消安静回到空闲，不弹错误也不推着重试。
- 失败或取消都**保留上一次的有效译文**和已经打好的字，可以直接再点一次重试，不用重打、不用重填 Key。

## 微信、QQ 这类输入框：实测结论

在你这台机器上实测了微信（Weixin，class `Qt51514QWindowIcon`）：

- 整个窗口的无障碍控件树**只有 8 个节点**，里面**一个输入框都没有**（`edits=0`）。
- 不是"接口读不到内容"，而是这个应用**根本没有把输入框注册给 Windows**。

微信的输入框本身是支持的（`mmui::ChatInputField`），但整棵控件树被一个默认关闭的开关挡住了，而且**按账号算**：没用过读屏模式的新号拿不到，旧的"开讲述人"办法也已失效。强行打开需要改微信自己的程序文件，我们不做——那个地址每个版本都会变，微信每次更新就失效一次，而且往别家软件里写东西无法对用户承诺安全。

所以这轮的改动是：**遇到这类应用时，把提示说清楚**。原来是"这个输入框暂时无法自动读取"，现在会说明是这个应用不给 Windows 开接口，并告诉你"复制内容后在浮窗里粘贴"同样能用。

**没有承诺做不到的事**：Ctrl+A / Ctrl+C 读剪贴板的方案我没有找到可靠来源证明它在 Windows 微信上真的可用，所以没有加进去。它还会覆盖你的剪贴板、破坏你正在选的字，而且锁屏或切走焦点就失效。如果你愿意在自己账号上试，我可以做了给你测。

QQ 暂时没测（你没开）。它是 Chromium 内核，和能用的 Discord 同类，**有可能跟微信情况不同**。
