# 1.0.2 · 千问工作空间不用手拼地址

日期：2026-10-05。

- 语音配置旁的 i 补上了工作空间 ID 在哪里找、官方指引和可复制链接。已经配置好的工作空间会显示已配置。
- “配置千问语音”可以只填工作空间 ID，程序生成对应接口地址；已有 ID 和地域会带出来，模型与音色按需展开。
- 根据当前 Key 和模型预选接口类型。新填工作空间 Key 却还没配地址时，点击主窗口确认会直接打开配置，不要求用户先理解报错再找入口。
- 取消额外配置会回到原窗口，已填 Key 保留；完成后接着保存，不需要再点一次主窗口确认。

## 本机故障核对

旧任务栏快捷方式能解析出正确目标，但 Windows 实际启动报“数据无效”；重建链接后桌面和任务栏入口都能启动。旧链接留有本机备份。这属于本机入口修复，不意味着新代码修复了所有 Windows 快捷方式问题。

当前两个 Key 可正常解密，完整千问地址也还在。配置位于用户 AppData，安装程序也在 AppData，均不在被整理的 work 文件夹里。没有证据证明文件分类删掉了配置；先前界面一度显示空值的原因尚未复现，不能据此编造结论。

## 用户操作负担

- 常规使用：沿用原有已保存配置，双击入口 1 次打开设置，额外填写 0 项、额外决策 0 次、外部切换 0 次。打开设置即可看到已填状态。
- 首次配置工作空间（从 API Key 已填好开始，操作数为路径估算）：主设置确认 1 次 → 程序自动打开配置 → 到控制台复制 1 个 ID → 回来点击 ID 框并粘贴 → 配置确认 1 次，接续原保存。应用内共 2 次确认、1 次点输入框和 1 次粘贴；外部控制台的登录、查询与复制操作尚未实测，不能省略为零。地域沿用正确值，只有不匹配时需要改选；模型与音色预设不适合账户时需调整。相对于旧版，不再手工拼整段接口地址。
- 异常配置：主设置确认后直接进入缺项配置，完成后自动接续保存；取消保留已填内容，不用重新填 Key。

新增供应商仍沿用此前的验证边界，本轮不消耗真实 API 额度。个人 Key、工作空间地址及本机故障备份不进入公开包。

检查：227 项基础与接口检查、包含皮肤的 283 项检查、12 项工作空间窗口操作检查通过。本机另有 4 项只读检查，确认两个 Key 实际加载进输入控件、工作空间完整、配置文件未修改。自动桌面截图工具本轮无法初始化，因此不把这些自动检查称为用户视觉验收。

安装后任务栏快捷方式冷启动约 1.2 秒打开设置（本机一次测量，非性能承诺）；重复启动仍保持同一个实例。更新前后配置文件校验值一致。
