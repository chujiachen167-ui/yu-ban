# 1.0.3 · 一句中文，紧跟一句英文

日期：2026-10-07 起，2026-10-11 定稿。

这一版有三块：**按句对照的排版**、**查词与中文方向**、**听的打磨**。

## 一、按句对照

浮窗从“整段原文在上、整段译文在下”改成按句对照：一句中文，紧跟对应的一句英文；下一句中文、下一句英文接着排下来。

- 翻译范围仍然只限你正在输入的这一句，但一句里再按**逗号和顿号**细分。写“明天要去见客户，还得带上合同，然后送他去机场。”会得到三组对照，而不是一整块。
- 逗号后面跟着「不过、但是、所以、and、but」这类连词时不断开——那半句是完整语义，切开就碎了。
- **分号不断**。没有标点的口语算一整句，不会被切碎。
- 组内两行靠得近，组与组之间稍微松一点。靠间距区分，不加分割线、卡片和说明文字。
- 长句照常换行，不截断、不缩小到难读，也不会出现横向滚动条。切出多少行都不设上限，靠展开后的滚动兜底。展开和收起用同一份内容。
- 输入英文时同样逐句对照：中文在上、原来的英文在下，原句不会被改写。
- 拖选、双击选词、跨句选择都还能用。复制按钮只拿走完整译文，不含原文。底部顺序是**朗读 → 查词 → 重新翻译 → 复制**，复制紧挨重新翻译。

**怎么做的**：一次翻译请求里就把整段和每个子句的编号一起交给模型，让它照着编号回译文。不会一个子句一次联网，也不会为了排版多问模型一次：等待时间和调用次数跟以前一样。模型没把某个编号还回来时，屏幕上只显示对上了的那几组，不编造也不回退成一整句。

## 二、设置与语音的整理

- **翻译不再被语音配置挡住。** 以前保存设置时会先校验语音，语音没配好就直接报错退出，刚填好的翻译 Key 存不进去。现在翻译先保存，语音的问题单独说明一句。
- 填了千问工作空间 Key 但没填工作空间 ID 时，可以直接取消弹窗：翻译照常保存，两把填好的 Key 都留着。
- 浮窗上**四种状态分得开**：翻译中、朗读中、失败、取消。失败会说明原因并保留重试入口；取消安静回到空闲，不弹错误也不推着重试；两者都保留上一次的有效译文和已经打好的字。
- 设置页加了「**我在学**」入口，位置在底栏。点开是上拉列表，选中英或中文。它决定翻译方向和朗读语言。
- **音色列表跟着你选的服务商和模型走。** 千问 Audio 3.1 有 15 个英语音色（4 个英式、11 个美式）；千问 TTS Flash 有含童声的 10 个；OpenAI 13 个内置音色。ElevenLabs 的内置音色 2026-12-31 到期，因此不列具体 ID。
- 模型不支持读法或音色时**直接置灰并写明原因和出路**，不让用户调了才发现没反应。
- 玻璃皮肤的窗口不再透出桌面上的文字；三套皮肤的设置页都不再压住角色形象。

## 三、查词与中文方向

- 浮窗底栏加了「**查词**」开关。打开后，输入**你正在学的那种语言的单个词**时直接查本地词典，给音标、词性与释义，不联网、不消耗额度。
- 学英语时查英文词（查 `record` 会给名词 `ˈrekɔ:d` 与动词 `riˈkɔ:d` 两个读音，重音位置不同）；学中文时查中文词。
- **短语、另一种语言、中英夹杂仍然走翻译**，所以这个开关不会把你卡住，不用来回切。
- 查词时**点朗读念的是这个词本身**，音标和重音正是要听的东西。
- 中文查词新增离线词典（CC-CEDICT，12.5 万词条，含繁体），拼音用带声调符号的写法（`měi lì`），而不是数字。
- **悬停取词对中文生效**。中文没有空格，取词改用词典做最长匹配：悬停「学」取到「学习」，而不是单字。同时修好了一个门控错误——以前只在译文行触发，学英文时悬停自己输入的英文原文永远查不到。
- **选中查词**。选中浮窗里的字词再点「查词」，查的就是选中的这一段；没选中时按钮仍是开关。中文词边界不明显，用户自己选比程序猜准。
- **量词单独标出**。词典里「大象」的量词是「头」，显示成「量词：头　一头大象」。此前把 CC-CEDICT 的内部标记 `CL:頭|头[tou2]` 原样搬进了释义，已改为生成时转成简体写法并存入独立字段。
- **例句**。词卡加「例句」按钮，向模型要一个日常用法，英文为主、中文为辅；只有点了才调用。

## 听：语速与重复

- 朗读偏好新增**语速**（慢／正常／快）。只在平台确实接受这个参数时才出现：OpenAI 用 `speed`、MiniMax 用 `voice_setting.speed`、千问仅 Audio 3.1 接受 `rate`、系统语音用自己的整数档。不支持的模型置灰并写明原因，不发出对方会拒绝的参数。正常档什么都不发，保持平台默认。
- **读法与语速相乘**而不是互相覆盖（清晰伴读 0.92 × 慢速 0.85 = 0.782，有测试守着）。
- **重复播放**（1／2／3 次或循环），跟读不必手点。默认 1 次，老配置读回来也是 1 次，不改变任何人的现有行为。循环设有上限，避免无人值守一直播。
- **修好一个缓存缺陷**：音频缓存键原来只含文本和语速，换了音色或模型还会播上一份录音。现在直接以请求体为键，任何会改变合成结果的设置都自然失效。

## 还没做好什么

- **只有 DeepSeek 与千问用真实账户调用过**；其余平台（OpenAI、Kimi、智谱、豆包、硅基流动、Gemini、Claude、MiniMax、ElevenLabs）均为离线模拟 HTTP 验证，型号、音色、套餐与地域权限未核实，详见 `docs/providers.md`。
- **语速的实际听感没有验收过**——各家的参数取值是按官方文档范围换算的，慢速和快速是否自然需要你试听判断。
- **例句的措辞质量没有系统性检查过**，它是模型生成的，措辞好坏需要实际使用反馈。
- **童声（Bunny、Pip）的英语音质官方文档没有说明**，只写了支持英语；值不值得长期用需要你试听。
- 微信、QQ 这类自绘输入框仍然无法自动读取。实测其无障碍控件树只有 8 个节点、不含输入框，即它们不把输入框注册给 Windows。强行读取需要修改微信自己的程序文件，本项目不做。遇到这类应用时界面会说明原因，并提示“复制内容后在浮窗里粘贴”同样可用。

## 检查了什么

- 基础与接口 583 项、浮窗与皮肤 740 项、千问工作空间 15 项、朗读偏好窗口 3 项，全部通过。
- 覆盖：逗号与顿号切分、连词不断开、缺编号时只保留对上的组；朗读与重新翻译在无结果时保持不可用而查词开关始终可点；音色目录按服务商与模型区分；三种读法确实发出不同请求；**语速能力判定与参数换算分平台核对，读法与语速相乘**；**音频缓存键随音色、模型、读法、语速变化而失效**；**中文悬停分词取到完整的词**；**量词从词典数据转入独立字段、内部标记不再进入释义**；设置里选的语言与查词开关能存下并读回；皮肤注册表与设置下拉一一对应。
- 三套皮肤的浮窗与设置页都渲染核对过：卡片不压角色、玻璃不透字、下拉文字垂直居中（偏心量实测为 0）。
- 没有调用真实 API，也没有读取个人 Key。发布包不含任何个人配置。
